# Phantom-animate architecture

Implements `animation-goals`. This is an architecture plan, not a description of an app that is already written. The user confirmed external FFmpeg, GPU rendering, and our own starter motions. The remaining technical decisions below come from research and have not yet been confirmed by building and running.

## Technical foundation

- **Bevy + bevy_egui**: scene, skinning, materials and render-to-texture from Bevy; the editor on egui. We do not build our own 3D engine on top of bare wgpu. Bevy 0.17.3 is verified by a build and headless rendering on Vulkan (see "Implementation status"); bevy_egui 0.38.0 and egui 0.33 are not integrated yet and are not verified by a build. Versions are pinned in Cargo.lock.
- **ufbx**: FBX and OBJ through our own adapter into the project format (crate ufbx 0.4). The Rust bindings use a C library, so a Rust application does not mean an all-Rust dependency tree. ufbx provides skinning and animation APIs, but no ready-made Bevy importer and no automatic retargeting.
- **FFmpeg/ffprobe as separate processes**: video/audio decoding, normalizing audio to a common format, and encoding MP4/H.264 + AAC. PNG and still images use the Rust image crate; audio output uses cpal. Availability and compatibility of image/cpal/rmcp are not verified by a build yet.
- **serde/JSON**: versioned project document; **rmcp** as the candidate SDK for MCP stdio. The local connection to the open app is a Unix domain socket, not a public TCP server.

Three domain Rust crates are enough: `core`, `runtime`, `app`. We do not create a crate per button or subsystem; the parts described below are internal modules. Desktop and headless are modes of one application. Network services, plugins and distributed rendering are not needed.

## Data ownership and dependencies

**core** owns the project document, commands, undo history, time, takes, scene state evaluation and audio mixing. It does not depend on Bevy, egui, MCP, the GPU or the windowing system. Document identifiers are stable and are not Bevy Entity IDs. The project stores scenes, Phantoms, independent volumes, skeletons, asset references, tracks, active takes, cameras and scene shots, drawings, and the film's sequence of scenes and shots.

**runtime** depends on core and implements file storage, import, FFmpeg, audio playback, the GPU representation of the scene, and export jobs. The Bevy World is a derived representation, not an alternative home for the project. GPU resources and transient media buffers are not serialized. A missing GPU does not block editing commands; a renderer is created only when an image is needed.

**app** depends on core/runtime and contains egui, MCP and the local bridge. Both surfaces call one dispatcher of typed commands, state queries and jobs. The UI never mutates the document directly, and MCP does not emulate keystrokes in order to set frames and actions precisely.

Dependencies point `app → runtime → core`; app also uses core types. One session owner applies changes sequentially. Background jobs work against a revision snapshot; the result of a stale job never replaces newer data.

## Commands and MCP

Commands cover creating/opening/saving a project, scenes and assets, Phantoms and actions, keys and takes, camera, strokes/painting, editing/audio, baking and export. Queries return the current revision, properties, time ranges and job results. The exact tool catalog is defined by the implementation of these operations, not by a separate feature set for the agent.

Every command validates IDs, types, number finiteness, ranges and asset availability before making a change. A change is atomic and has one undo step; a brush stroke and a take are whole operations, not thousands of separate undos. MCP action recording sets times explicitly and does not depend on how fast requests are delivered. Long-running import, bake and export return a job ID and progress, report errors, and support cancellation.

MCP responses follow one uniform machine-readable contract, with no legacy text-JSON fallback. Success carries the operation-specific object directly in `structuredContent` (no artificial `data` wrapper); the regular `content` is empty. Every successful document mutation is centrally augmented with post-command `revision`, `next_id` and a canonical compact `entity` (type, stable IDs and current fields; deletion is `removed: true`), so the agent needs no follow-up `scene_get`. The snapshot is built from the already-mutated `Project`, and one user mutation corresponds to one revision and one undo step; `history_undo`/`history_redo` return the current revision and `{kind: history, operation, applied}`. Operations are classified explicitly: creating/opening/saving a project and locking are lifecycle, and queries plus render/job are not document mutations and do not get `revision`/`next_id`/`entity`. A tool error carries `isError: true` and `structuredContent: {code, message, details}`; the stable snake_case `code` and the `details` fields come from a typed error variant, not from parsing a localized `message`. Text content never contains serialized JSON. Local parameter errors use the code `invalid_input`; state, IDs, paths and lock owners are passed in `details`. Standalone and the GUI bridge use one MCP-envelope helper. The internal newline-JSON bridge returns either a structured `result` or `error_data` of the same shape and has no string `error` field.

Render job diagnostics: the child process's stderr is collected by an asynchronous stream into a bounded ring buffer (the last ~64 lines / ~8 KiB) while stdout stays a clean progress protocol; `job_status` returns completion, exit code, parsed progress (frames_done/total), elapsed time and the stderr tail, and `job_list` returns the status of every job in the session. Committing completion joins both pipe readers (stdout and stderr reach EOF after the child exits) and drains the progress channel once more, so the last progress line and the stderr tail are guaranteed to land in the status instead of being lost to a race with the reader threads. State queries are augmented with snapshots: `scene_get` returns a full serde snapshot of the scene, `asset_list` returns assets (id/kind/path). `render_still` renders one PNG frame inside the session owner and is available both standalone and through the bridge; the MCP response contains one image block and a `structuredContent` with `scene/frame/shot/width/height/mime_type`, but does not duplicate the base64 PNG in the metadata. The operation requires a GPU and validates dimensions (<= 4096) before touching the device; errors use the shared structured envelope. The `report: true` option (corrective C3.2 — the agent's "eyes") adds pure frame metrics to `structuredContent` without re-decoding the PNG: `mean_luma`/`luma_p5`/`luma_p95` (Rec.709, opaque pixels only), `empty_coverage` (the fraction of the frame with alpha == 0, i.e. no geometry — the same method as in the A3 measurement), `objects_in_frame`/`objects_total` (a Bevy visibility fact: an object counts if at least one of its Mesh3d parts passed the selected camera's visibility; this is not a background alpha heuristic), and the non-cryptographic `scene_digest` (64-bit hex of the canonical serde scene snapshot; it changes on any change to the scene document). The MCP tool renders 1024x576 by default and a cheap 480x270 preview with `report: true`; the metrics are computed by `phantom_runtime::render::metrics::frame_metrics` over the RGBA readback, so they are deterministically testable without a GPU and are equally available standalone and through the bridge.

Getter queries (corrective C3/D2–D4): `shot_get {scene?, shot}` — a full canonical shot snapshot (id, name, range, camera with its keys and focal_mm) plus the parent scene's id and current revision; `asset_get {asset}` — the canonical asset (id, kind, relative path, `exists` — a file at that path inside the project directory) and cheap usage references (the scene background and video background, objects, the Phantom's imported rig, the legacy clip, track uses of the clip, and the audio clips of scenes and the film); a nonexistent id yields the stable `not_found` with `nearest_ids` (up to 5 closest existing ids by numeric distance) in `details`. `film_get` returns the film's ordered clips and the mapped total length in frames at 24 fps and in seconds. Getters are pure queries: they do not bump the revision, do not create undo steps, and do not get the mutation acknowledgement `revision`/`next_id`/`entity`; where applicable their values include the current project revision. `project_recent` returns the last successfully created/opened project directory even after the process died, plus the current directory, revision and active scene of this MCP session; it works with no project open. Persistence of the "last project": after a successful `project_new`/`project_open`, the path and a unix time are written atomically (temp file + rename) to per-user state at `$XDG_STATE_HOME/phantom-animate/recent.json`, falling back to `~/.local/state`; only the path and timestamp are stored, never lock tokens. A corrupt or unreadable file produces a warning (`recent_state_corrupt`/`recent_state_unreadable`) and an empty answer but does not prevent the server from starting; a successful project open rewrites the file. The state path is injected into `Session` for deterministic tests (no mutation of global environment and no test touching the real user file).

`batch {ops}` is an atomic package of document mutations (corrective C3.8): operations in wire format carrying an `op` tag are executed sequentially by the regular Session dispatcher (the same validation and the same deterministic id allocation as single calls — scene→phantom→key chains work inside one package), but each operation's class is checked up front: only document mutations are allowed, and nested batches, queries, lifecycle and render/job are rejected before any document changes (`invalid_input` with `index`). If any operation fails, the project and history are restored from a deep snapshot — no partial state, no extra undo steps and no spent ids remain; the `batch_failed` error carries `index`, the operation name, the inner `code`/`cause` and `rolled_back: true`. On success the package's undo steps are collapsed into a single `Command::Batch` step (`History::squash_last`) and the revision is normalized to +1 for the whole package; the acknowledgement is `applied`, `results` (per-op created ids and canonical `entity`, without intermediate revision/next_id), plus the final `revision`/`next_id`/`entity` of the last operation. Undo rolls back the whole package in one step and redo reapplies it with the same ids. The core `Command::Batch` provides the same atomicity for direct application: commands are executed against a draft document and the document is left unchanged on error; an empty and a nested batch are `InvalidBatch`. The MCP `batch` tool takes an array of JSON operations and substitutes the connection's active scene into operations without a `scene` field; unlike the single convenience tools, wire-format angles are radians and audio is samples at 48 kHz (this is documented in the `ops` field description and in the server instructions).

Effects and post-processing (corrective B3): `scene.grade: Option<SceneGrade>` — frame color grading through Bevy's `ColorGrading` (exposure EV, temperature/tint, hue, post_saturation plus saturation/contrast/gamma/gain/lift sections; LUTs are not supported); `scene.fog: Option<SceneFog>` — exponential `DistanceFog` (color + density > 0). `scene.vfx: Vec<SceneVfx>`: `particles` — a deterministic hash simulation (splitmix32 by particle index, no RNG state: a frame does not depend on render order; cap of 1024 quads; unlit alpha-blend, Y-billboard toward the camera, sin fade at the ends of a particle's life) and `water` — a plane with a normal map (asset) and UV scroll via `uv_transform` over time; presets `snow|embers|smoke|rain` (gravity < 0 — falling, > 0 — rising); `keys: Vec<VfxKey>` — enabled/density steps keyed off elapsed time; `attach` — an emitter on a bone (B2). The `SetGrade`/`SetFog`/`AddVfx`/`RemoveVfx`/`SetVfxKey`/`RemoveVfxKey` commands validate before mutating; MCP `grade_set`/`fog_set`/`vfx_add`/`vfx_remove`/`vfx_key_set`/`vfx_key_remove`. Bloom/vignette/depth_of_field/god_rays are deliberately deferred: the available set of Bevy 0.17.3 crates has no camera components for them (verified against the registry sources), and god_rays needs a custom shader.

Materials (corrective B4): `Phantom.material_patches`/`SceneObject.material_patches: Vec<MaterialPatch>` — patches (target by mesh-part material name or all; base_color sRGB, metallic, roughness, emissive linear > 1 allowed, opacity < 1 enables alpha blend, unlit) on top of the asset's imported materials: the asset is not mutated and undo is one step. `material_preset`: matte | skin | metal | wet | glass | glow — names beat bare numbers. The `SetMaterialPatches` command (exactly one owner, range validation before mutating); MCP `material_set` (preset + explicit fields override it, clear removes it) and `material_list` (the model's mesh parts: current import values and effective values after patches; builtin actors without file IO). Rendering: a patched material is a clone of the asset when the target matches, and the model fill cache is not broken; spawning actors and props goes through one `apply_material_patches` path.

Attachments (corrective B2): `SceneObject.attach`/`SceneLightSource.attach: Option<Attachment>` (phantom + bone name + offset in bone space, radians) — the transform is recomputed from the pose every frame: world = Phantom root (position + yaw + `phantom.scale`) ⋅ accumulated bone hierarchy (`rig::accumulate_bones`, topological order; builtin — `rig::actor_bones`, imported rigs — SkinData, the hierarchy has been stored in PhantomEntities since forge) ⋅ offset; the bone name is matched case-insensitively. An attached object's own transform keys are not applied (the key's scale is inherited on top of the actor's scale); for an attached light source the intensity/enabled keys do apply, the transform ones do not. The `AttachObject`/`AttachLight` (None — detach) and `SetPhantomScale` (finite > 0) commands validate that the phantom exists and the bone name is non-empty before mutating; MCP `attach` — one shape: object | light | prop (creates an object from an asset and attaches it in one call — "a flashlight in the hand"), `detach: true` detaches; `phantom_scale_set`. The actor's scale (`phantom.scale`, serde default 1.0) is applied to the root entity. Forge tests without a GPU: the object follows the bone across frames, and scale lands on the root.

Scene staging (corrective B1/B5): the scene stores `lights: Vec<SceneLightSource>` — document light sources point (lumens) / spot (lumens + cone in radians) / directional (lux) with a name, color, on/off, opt-in `shadows`, and `LightKey` keys (pose + optional intensity/enabled on a frame). `SceneLightSource::at(frame)` — one semantics: with no keys and before the first key — the `rest` pose; between keys, linear interpolation of the transform and of the EFFECTIVE intensity (None inherits the source's body value), yaw along the shortest arc, enabled a step from the last elapsed key (the future never looks into the present). The `AddLight`/`RemoveLight`/`SetLightKey`/`RemoveLightKey` commands validate (cone in (0,π), finiteness) before mutating and undo in one step; MCP `light_add`/`light_remove`/`light_key_set`/`light_key_remove` take degrees. `scene.ambient` (`AmbientMode::FromBackground|Fixed|Off`, serde default from_background — the previous behavior) separates ambient from the background: fixed/off are set at forge and are not overwritten by a video background. `scene.sky` (B5, linear RGB) — a clean frame color: the camera's clear color instead of transparency, which makes the frame opaque; MCP `scene_ambient_set`/`scene_sky_set`, commands `SetAmbient`/`SetSky`. Forge and `apply_scene_frame` spawn and animate the sources without rebuilding the world (LiveSync rebuilds on a revision change); forge tests without a GPU cover spawning (cone/lumens/shadows), per-frame key application, and the ambient/sky modes.

Audio pipeline (corrective A4/A6/B6): `AudioClip` has `fade_in_samples`/`fade_out_samples` (serde default 0 — old projects have no fades) and the mixer applies a raised-cosine (equal-power) gain per sample; the `UpdateAudioClip` command is a targeted patch of offset/len/fades with validation before mutating (a fade is no longer than the clip, len > 0; `AudioClipNotFound` is a stable `not_found`). MCP: `audio_clip_add` takes `fade_in_secs`/`fade_out_secs`, `audio_clip_update` takes a partial patch in seconds; CLI: `clip-add --offset-secs/--len-secs/--fade-in-secs/--fade-out-secs` (mutually exclusive with the sample forms) and `clip-update`. Peak normalization of the mix is a deliberate opt-in: `FilmExportOptions.normalize` (default false) with `target_peak_dbfs` (default −1.0) scales the whole mix by a single linear coefficient from the peak, `mix_film` still returns the peak and it is now used; CLI `render-film --normalize --target-peak-db`, MCP `render_film` — `normalize`/`target_peak_db`. `phantom-animate render-audio` mixes the film to WAV without rendering video (a preview of the mix). Loudness metrics are RMS/peak dBFS (audio_report), not K-weighted LUFS; ducking, a limiter and SFX track types are deliberately deferred. The background `zone_averages` are averaged with alpha weighting (A7): a semi-transparent PNG no longer drags ambient to black, and a fully transparent zone is a neutral 0.

`audio_report {scene?}` (corrective C3.4/A4) is a checkable fact about sound before rendering: track and clip durations in seconds against the length of the scene/film, RMS and peak dBFS of the fragments actually used (offset..offset+len; the "near silence" threshold is −60 dB — the case of a track's quiet intro), and warnings `audio_beyond_video`/`audio_beyond_source`/`quiet_fragment`/`audio_longer_than_video`/`decode_failed`. Decoding is lazy, once per unique (asset, offset, len), through ffmpeg (`ffmpeg_available` — a cheap `ffmpeg -version` run); without ffmpeg or without a project directory the report degrades to document data with the `ffmpeg_unavailable` warning, and a decode error for one asset is a per-clip `decode_error` — the report does not fail. The operation is a Query (no revision/entity). `state_get` additionally carries `audio_summary` (video/audio/lost_seconds per scene and for the film) from pure document data without decoding. `film_add` returns `warnings` with `audio_longer_than_clip` when the edit range is shorter than the scene's longest audio track.

`job_wait {job, timeout_secs}` blocks the call until the job finishes or the timeout expires, then returns the same shape as `job_status` plus `timed_out` (true only when the timeout expired while the child process was still alive; no cancellation is implied). `timeout_secs` must be finite and within 0..=300, otherwise `invalid_input` before the first poll; waiting is a poll with a pause ≤ 20 ms, no busy-spin; completion observed inside the wait finalizes the exit code and the stderr tail through the same path as `job_status`, and a zero timeout validates the id and returns the status immediately. The operation lives in the shared Session/Op dispatcher, so the bridge gets it without a separate implementation; the bridge connection is held until it returns. `describe {tool}` returns the name, description, inputSchema, outputSchema and notes on units/usage, generated from the same ToolRouter metadata as `tools/list` — one source of schemas, no manual duplication, and drift between `describe` and `tools/list` is excluded by a test; an unknown tool gives the stable `not_found` with `nearest_tools` (up to 5 closest registered names).

Pure document diagnostics (corrective C3.1/C3.3, no render and no GPU) live in `app/analysis.rs` and share formulas with the renderer: the vertical FOV has a single source, `phantom_core::vertical_fov` (`2·atan(12/focal_mm)`, a sensor 24 mm high), used by both render sites (`forge` and the per-frame update) and by diagnostics; the horizontal FOV is derived from it through `phantom_core::horizontal_fov` with the aspect ratio (the MCP parameter `aspect`, 16:9 by default). The camera for diagnostics is `Camera::sample` plus the same basis as in the renderer (`YXZ(yaw, pitch)`, looking down local −Z), and the screen is the same geometry that `mesh_gen::arc_screen_mesh` builds. Three Session operations of class Query (they do not bump the revision, no `entity`/`next_id`, no undo steps) and same-named MCP tools with documented fields (degrees out, frames at 24 fps in): `validate {scene?}` runs the invariants — screen geometry (`bg_geometry_invalid`, error), FOV coverage at camera keys and at the ends of scene and shot ranges (`screen_fov_gap`, warning; suggested_fix names the arc needed in degrees or the limiting focal_mm, and if the radius cannot close the frame even with a full circle it points to `background_fit`), motion coverage holes (`motion_gap`; a phantom with an active take covering the scene, or a legacy clip, is skipped), audio clips outside their owner's range and track lengths (`audio_out_of_range`/`audio_length_mismatch`, frames + seconds), edit clips outside the scene/shot (`film_clip_out_of_scene`, error), missing asset files (`asset_missing`, error; relative to the project directory), film assembly checks (`shot_not_in_film` — a shot not assembled when the edit uses shot references at all; `film_coverage_gap` — scene frames never shown; `film_overlap` — some frames shown twice; all warning), a phantom without motion and an empty scene (info). The response is `{ok, revision, findings:[{code, severity, where, why, suggested_fix}]}`; ok=false only for error-severity; finding order is deterministic (scene, code, frame; project-level findings first); with no `scene` and no active scene — the whole project. `camera_coverage {scene?, frame?, shot?, aspect?}` returns the camera pose and FOV in degrees, the azimuthal/vertical screen span seen from the camera, the gaps `gap_deg` per side, and a point `in_frame` test for each phantom/object; the default frame is the start of the shot/scene range; with no background, `background: null` plus the finding `background_absent`. `background_fit {..., margin_deg?, shot?}` (default margin 5°) without `shot` computes over the WHOLE scene (corrective_2 K0.1): it samples the legacy camera's keys and each shot camera's keys, and the arc/radius/height must cover every sample — that is, the union of the shots' requirements, not one camera (a shot looking elsewhere would otherwise leave a hole in its own frame). The response carries `scope` (`scene`|`shot`), `cameras`/`samples`, `shots[]` with each shot's worst frame (`covers_current`, `gap_deg`, `needed_arc_deg`) and the top-level camera of the binding sample, plus `suggested {arc_deg, radius, height, center}`, `panorama_aspect = (arc·radius)/height` for the panorama generator, `current`/`delta`, `fits` and `arc_covers`. An explicit `frame` without `shot` is `invalid_input`, not silently ignored: shots have their own ranges. The approximations are fixed in the module document: coverage is estimated from 129 arc points and two edges (sampling error < arc/128 rad), vertical coverage from the worst column inside the frustum (conservative), screen points behind the camera are excluded from the span (a full circle correctly wraps the camera), and the point test uses the root point without model volume. Fitting keeps `center`, starts `radius` at `max(current, dist_xz(camera, center) + 0.5)` from the most demanding sample, and grows it in ×1.5 steps until a bisection over the sampled span finds an arc that closes all samples (the screen's bulge faces the camera, so the starting radius may not be enough; the 10 km limit guards against degenerate stagings); `height` is the union of the vertical requirements (the highest top and the lowest bottom among samples) from tan(pitch ± (vfov/2 + margin)) clamped to ±85°; results are rounded up (0.1°/0.1 m/0.01 m) and do close the frame — fixed by a fit→coverage roundtrip test and by a scenario test covering two opposite shots. `shot_report {scene?, shot, every?, width?, height?}` (corrective_2 K0.2) gives the agent "eyes" on the whole shot rather than one frame: it renders a sample of the shot's frames with a single renderer (without `every` — up to 5 evenly spaced points including both ends; with `every` — every Nth frame, hard limit 12 frames so the report does not become a render of the whole shot) and returns `rows[{frame, mean_luma, luma_p5/p95, empty_coverage, objects_in_frame}]`, `aggregate` (mean/min/max brightness, maximum emptiness, how many objects are visible) and `findings` (`empty_frame`, `shot_empty`, `objects_out_of_frame`). It is a Job-class operation, without `revision`/`entity`; dimensions/references are validated before touching the GPU. A preview of the whole film is the CLI `render-film --preview --every N`: the same clip→scene mapping and shot camera as the export, but into a PNG contact sheet (480x270 by default), without MP4 and without sound. The tools are mentioned in the server instructions and in `studio_capabilities.features.pure_diagnostics` (for pure queries); bridge parity comes from the shared Session Op, with no separate implementation.

In windowed mode the MCP bridge connects to the owner of the open project. In standalone mode stdio creates a separate session without a window; logs go to stderr and stdout carries only the protocol. The socket lives in a private runtime directory of the user with restricted permissions. File access is limited to allowed roots; canonical paths, symlinks and escaping a root are checked. Loading external textures does not give the importer unlimited filesystem access.

The MCP server keeps a navigational `active_scene` separately for each stdio server/bridge connection: creating a scene selects it, opening/creating a project selects the first scene or `null`, and the disappearance of the selected scene selects the nearest remaining stable ID (the smaller one on a tie) or `null`. `scene_select` is the only explicit scene operation that changes the selection; other tools take an optional `scene` and, when it is omitted, resolve it at the MCP boundary or return the stable `no_active_scene`. The Session `Op` still requires a scene ID and does not own MCP navigation. `state_get` is augmented with `active_scene` and `allowed_root`. `studio_capabilities`, without a GPU probe, reports the contract/protocol versions, standalone/bridge, root, platform, the fixed 24 fps/48 kHz, limits and features; the GPU stays `unknown_until_render`.

MCP schemas describe every field (units, range, semantics) and tools/list always carries an object `outputSchema`; `structuredContent` stays authoritative. At the MCP boundary angles are named `*_deg` and converted to core radians, audio is given in seconds and converted to 48 kHz samples, and motion uses typed objects instead of tuples or a parallel yaw. `key_set` preserves omitted components from the exact key or from the evaluated state by default, and lights update with patch semantics. Drawing normalizes `canvas|screen|ndc` to a canonical 1920×1080 canvas. `render_scene.out` defaults to `<project>/frames`, and the render range is a typed `[start,end)` with end exclusive.

One project is never written by two sessions at once: a writer lock, and a second process either connects to the existing session or opens a separate copy. While a recording is live, commands that change that scene are rejected as busy; state queries and stopping remain available. This prevents an agent from silently interfering with the director's performance.

## Time, performance and take

Edit timing is whole frames at 24 fps; audio is normalized to 48 kHz, that is 2000 samples per frame. Lengths and trims are half-open ranges `[start, end)`. Source video timing is read from timestamps rather than assumed to be a constant FPS.

Live control is integrated with a fixed step of 1/120 s; input events carry monotonic timestamps. Playback with sound syncs to the audio clock, and to the monotonic clock without a device. Preview may drop displayed frames under load but never time for recording. Transformations and action transitions are recorded, not just keys. Offline export computes each frame's concrete time independently of wall clock and GPU load.

A take stores a range and its own tracks. Re-recording creates a new take; unrecorded parts keep referencing the original performance version, without destroying the old take. Manual keys and clips resolve into one evaluated performance; new recordings do not stack movement twice.

Implemented: `Take { id, name, range, motion }` and `active_take` on Phantom (serde default — old manifests still load); the active take overrides the manual track only inside its range, and outside it manual keys apply; recording commits `AddTake` (one undo); the UI offers selecting the active take and deleting it; MCP — take_add/take_active/take_remove.

Root movement is driven by the Phantom controller. For automatic walk/jump, a clip's root motion is separated from the controller's movement so displacement is not doubled. The volume does not inherit the character's movement; the floor constraint applies to a specific reference point of the controller and is not a collision simulation of the whole model.

In "on twos" mode, only the evaluation of the Phantom's pose and position uses the time `floor(frame / 2) * 2 / 24`, anchored to the start of the scene. Camera, background and audio are evaluated at normal time. Recording stays full: twos mode does not delete the source data. That is why, with a moving camera, you cannot simply copy every PNG twice.

## Scene objects (props)

An object is a static (non-skinned) placement of an imported OBJ/FBX model in the scene, not an animatable character: no actions, skeleton or takes. `Scene.objects: BTreeMap<ObjectId, SceneObject>` (serde default — old manifests load empty); `SceneObject { id, name, asset, keys: Vec<ObjectKey> }`, where the asset must be a `ModelObj`/`ModelFbx` (the `AddObject` command rejects other types). `ObjectKey { frame, position, yaw, pitch, roll, scale }`: yaw is primary, pitch/roll/scale are optional in the manifest (default 0/unity); number finiteness and a positive scale are validated before applying.

An object's transform at a frame is a pure function `evaluate_object` (pose-style, shared by the renderer, the GUI and tests): position and scale are linear, angles take the shortest arc, outside the key range it holds, and an empty track keeps the source transform. "On twos" mode quantizes the frame with the same rule as the Phantom (from the scene start), before sampling. The `AddObject`/`RemoveObject`/`SetObjectKey`/`RemoveObjectKey`/`ReplaceObjectMotion` commands are atomic with a scene snapshot, an undo step and a revision bump. Rendering: forge spawns the object root with the model's parts/materials through the shared loading path; a skinned model renders in bind pose with no clip and no outline; `apply_scene_frame` sets only the root transform. Surfaces: Session Ops and MCP (`object_add`/`object_remove`/`object_key_set`/`object_key_remove`, listed in `state_get`), CLI (`add-object`, `set-object-key`), GUI (an object outliner with minimal key editing).

## Import and assets

The ufbx adapter normalizes axes, units (meters), hierarchy, bind matrices, weights, materials and tracks. Internal coordinates: a right-handed system, Y up. Material and influence-count limits are checked explicitly; invalid data is not silently turned into a static model.

Verified by a build on the CC0 KayKit rig (a mixamo-like path; literal Mixamo files were not tested). Fixed importer invariants: the skeleton is assembled globally across all skinned meshes in the file (a character may have several meshes on one skeleton); vertices are baked into one shared bind-pose world via geometry_to_world, and inverse bind comes from `cluster.bind_to_world` (not geometry_to_bone — that depends on the space of the specific mesh); the bones' rest pose is derived from the bind matrices, not from the current node local transform.

A clip without a mesh attaches only to a compatible skeleton: names after normalization, the hierarchy and the bind/rest pose are checked, not a single matching bone name. Implemented: `load_clip` samples a stack by name at 24 fps (`stack`), and with no name the longest one (legacy); by default compatibility is by full bone names (hierarchy/bind are not compared — noted as a limitation); zero matches is the `NoMatchingBones` error and an unknown stack name is `NoSuchStack`. `Phantom.clip_track: Vec<ClipUse>` — an ordered sequence of clip uses (a MotionFbx asset, stack, range inside the scene, speed > 0, blend_in/blend_out >= 0, root-motion owner); overlapping uses on one Phantom are rejected by the commands (`SetClipTrack`/`AddClipUse`/`RemoveClipUse`, atomic, one undo). Outside uses, the controller's manual keys / bind pose apply. Sampling inside a use: `(frame - range.start) * speed` clip frames, clamped at the last frame (no looping). Blending inside the blend_in/blend_out windows: lerp of translations and nlerp of rotations toward the base pose — rest at the track edges, the neighboring clip's pose exactly at the seams. Root motion: `Controller` by default — the clip pose is applied as sampled and the controller owns the root entity's displacement; `Clip` — the clip's root-bone delta from the use's start frame goes to the root entity (world = controller base + delta), the controller is frozen at the start frame, and the root bone's translation in the pose is frozen at clip frame 0 so movement is not counted twice (trajectories are not summed). The schedule (which use, clip frame, blend weights) is pure core functions (`clips.rs`); root motion and sampling are applied by runtime, where `ClipData` lives. An empty `clip_track` is the legacy path `phantom.clip` (the longest stack looped for the whole scene, behavior unchanged; no migration). Universal transfer of motions between arbitrary rigs is not promised.

Retargeting is explicit, via profiles: `ClipUse.retarget: Option<RetargetProfile>` (serde default `None` = direct name matching, previous behavior). The `Humanoid`/`Quadruped` profiles (core, `retarget.rs`) declare a canonical minimal set of roles (humanoid: hips/spine/chest/neck/head, shoulders, upper arm/forearm/hand, thigh/shin/foot ×2; quadruped: body/neck/head/tail and front/hind pairs + lower ×2, as in the builtin wolf/horse) and, for each role, a list of accepted bone names: Mixamo `mixamorig:*`, Phantom's builtin rigs (`upper_arm_l`, `front_lower_l`…), common KayKit/Blender variants. Matching is on normalized names (case, the prefix up to the last `:` and the separators `. - ` are ignored), exact equality, no substrings; one source bone is claimed by at most one role. With a profile set, the loader (`load_clip_retarget`, runtime) finds the source bones in the file by the role patterns and moves the track samples onto the target rig's bone names (`ClipData.bones` — target names, after which the shared bone→track map path continues). Roles without a partner on either side are non-fatal diagnostics (warn at forge; the clip plays the matched subset and bones without a track stay in rest pose); zero coverage is the same `NoMatchingBones` error, not a silently mangled animation. The transfer limitation is fixed: rotations and translations are transferred directly (assuming matching bone orientation), with no rest-pose orientation correction and no scale correction — differences in rest poses may require tuning/extending the profile's patterns. The clip and map cache key includes the profile. Surfaces: MCP `phantom_clip_set` (the `retarget` parameter, only in track form), CLI `set-clip --retarget`, and a "retargeting: none/humanoid/quadruped" combo box in the GUI's clip track row. The builtin simple motions use the documented humanoid profile; a mismatch reports a clear error instead of emitting mangled animation. OBJ contains no animatable rig.

Implemented (materials P0): OBJ/FBX import with materials per mesh part. `ModelData` carries a `MaterialRecord` table (base color sRGB + texture, metallic/roughness, normal map; serde default — old data loads with an empty table) and a partition of the `parts` index buffer by material with no gaps or overlaps; the vertex/skin arrays are shared and the outline is one combined hull. Reading: `pbr.*` from ufbx with a fallback to `fbx.*`, OBJ-MTL via `load_external_files` (Kd/map_Kd/Pr/Pm/norm). A triangular face is not passed to `ufbx::triangulate_face_vec` (version 0.4 returns an empty index list for it) and keeps its three indices directly; an n-gon goes through the triangulator. That is why a static OBJ cannot be "visible in the document but with no primitives on the GPU". Rendering: one Mesh3d entity per part, material is a StandardMaterial; the base-color texture is decoded as sRGB, normal and metallic/roughness are linear; separate metallic/roughness maps are packed on the CPU into G=roughness/B=metallic with neutral 255 channels, and a matching combined map is treated as the glTF layout; spec/gloss files (roughness_as_glossiness) invert the factor and the G channel; tangents are generated for normal-mapped parts. Texture paths are resolved inside the project root (canonicalization, refusal to escape), and an unavailable texture is a warning plus the factor. Unsupported features (layered/procedural textures, heightmap bump, per-map UV transforms) are explicit diagnostics in `ModelData.diagnostics`/a render warning, not a silent white mesh.

Model import is bundled: the CLI import, the GUI import button and the Session Op::AssetImport put the OBJ/FBX together with its MTL and textures into their own bundle directory `assets/<name>[-n]/`, preserving the relative layout, so the bundle is self-contained after the source is deleted. Every dependency path is canonicalized and must stay inside the source directory; escaping via `..` or a symlink rejects the whole import (the half-assembled directory is removed). Limits: ≤64 dependency files, ≤256 MB total, textures ≤8192px. Textures embedded in an FBX are extracted to the bundle root; missing ones are a diagnostic, not a rejection.

### Camera (corrective_2 C1/C2)

A camera key (`TransformKey`, shared by the scene's legacy camera and shot cameras) carries, besides the pose and angles, optional `roll` (horizon tilt), `look_at` (aim point), `focal_mm` (focus on the key) and `ease` (segment curve); all are serde default, so old manifests load unchanged. `look_at` overrides a given yaw/pitch: the direction is computed with the renderer's basis (`YXZ(yaw, pitch)`, looking down local −Z), so the frame matches what the camera sees and the agent needs no trigonometry for orbit/follow. The single interpolation point is `Camera::sample`, returning `CameraPose {translation, yaw, pitch, roll, focal_mm}`; both the renderer and the pure diagnostics use it, so coverage always matches the frame, including a zoom inside a shot. Interpolation behavior: the segment fraction is shaped by the starting key's `KeyEase` curve (`linear|ease_in|ease_out|ease_in_out`, cubic with no new dependencies), yaw takes the shortest arc (the previous linear interpolation took a turn from 170° to −170° "the long way"), focal length interpolates linearly, and a key without its own `focal_mm` takes the camera's base focal length. The `Command::SetCameraKeys`/`SetShotCameraKey` commands check pose/angles/roll/target finiteness and a positive focal length before mutating. Surfaces: MCP `camera_key_set` (no `shot` — the scene camera, with `shot` — the shot camera), `shot_camera_key_set`, `shot_focal_key_set` (zoom without changing the pose), `shot_focal_set` (the base lens); CLI `set-camera --roll --look-at --ease --focal`. Lens presets (`ultrawide 16 | wide 24 | normal 35 | portrait 50 | portrait_tele 85 | tele 135 | super_tele 200`) are accepted by the `focal_preset` field; an unknown name is `invalid_input`, not a silent default. Deliberately deferred: deterministic camera shake, motion presets (dolly/pan/crane/orbit/follow/handheld), and aperture/depth of field — the first two need a separate decision about data shape, and the available set of Bevy 0.17.3 crates has no suitable DoF component (see the bloom/vignette decision).

### Metric prop catalog (corrective_2 K1/K3)

`phantom_core::catalog` — one `CATALOG` table instead of verbal agreements: each entry has a name, a section (`primitive|furniture|interior`), full dimensions in meters, an origin (at base center — the item stands on `y = 0` rather than sinking into the floor), named material groups (matching `target` in `material_set`) and a hint for the director; interiors additionally have `open_sides` (walls that are not built: the camera's side does not block the frame) and `openings` (doors). Runtime builds the geometry (`props::prop_model`) procedurally from this table — no external files and no licensing questions; tests compare the generated mesh's dimensions against the table, check that the material partition has no gaps, and check that a cut-out wall really is not built. Sizes in JSON are rounded to a millimeter (`builtin::mm`): the table stores f32, standalone and bridge serialize f32 differently, and without rounding the same catalog would look like different numbers. A scene object gained `builtin: Option<String>` (serde default — old manifests load as before): with a name given, the mesh comes from the catalog, no asset file is needed, and every existing mechanism (transform keys, bone attachment, material patches) works unchanged. Surfaces: MCP `catalog_query {kind?, query?}` (search by section and substring) and `prop_add {scene?, name, prop, pos?, yaw_deg?, pitch_deg?, roll_deg?, scale?}`, CLI `catalog [--kind] [--query]` and `prop-add`; `builtin_catalog` additionally returns `props`, `human_roles` and `animal_heights_m`. An unknown name is `not_found` with `details.hint = catalog_query`, an unknown section is `invalid_input`.

The proportion table (K3) is the same source of truth: `HUMAN_ROLES` (child/teenager/adult/elderly: height, eye, shoulder, hip, knee) and `ANIMAL_HEIGHTS` (builtin actors). Adult height stays 1.74 m — a product decision, and props are built in meters. The horse in the table is above human shoulder height (1.62 vs 1.43) — the edit was made upward, as the report's author asked.

A project is a directory with a JSON manifest, source/created assets, and a separate recoverable cache. Import copies allowed assets into the project; references are relative. Sources are kept; normalized mesh/clip and previews are derived data. Saving first writes the new assets, then atomically replaces the manifest; a crash never leaves a manifest referencing unwritten files. An unknown newer schema version is not overwritten. A missing asset is flagged and blocks the export that depends on it, but not the opening of the remaining data.

Existing `.blend` files, OBJ, images and bakes in the repository are not automatically considered licensed bundle assets. The builtin set needs its own provenance and an explicit license; imported Mixamo files are not redistributed with the app.

## Rendering, background and projections

One GPU renderer serves the viewport and offscreen export without winit/a window. Without a suitable GPU, editing stays available and an image request returns a diagnosable error; a CPU renderer is not promised.

The arc screen's orientation is fixed (corrective A3): the formula `z = (cos θ − 1)·R` places the arc's midpoint at `center` nearer the viewer and pushes its edges away — the bulge faces TOWARD the camera (the screen is a backdrop); the comment in `mesh_gen::arc_screen_mesh` now matches the code. A configurable orientation ("the screen wraps around the scene") is a separate decision outside the MCP stage; until then `camera_coverage`/`background_fit` compute coverage from the actual geometry. The elliptical screen mesh uses arc-length-uniform UVs. The image/decoded frame defines the visible background, while regions averaged in linear color space give the colors of a small set of virtual sources behind the characters. This is an approximation, not physical emission. The old browser experiment is a math reference; its pre-distortion does not carry over into the product automatically.

Implemented: `BackgroundSource` (untagged: old manifests holding a number read as an image); `Background.bulge` (`toward_camera` — the arc's midpoint is nearer the viewer, a backdrop screen, pre-A3 behavior; `away_from_camera` — the edges are nearer, the screen wraps around the scene) and `Background.fit` (`cover` — aspect-preserving crop of the panorama, `contain` — the whole picture with clamp bands, `stretch` — the previous stretching); the serde default of both fields is `away_from_camera`/`cover`, which deliberately changes how old scenes look (corrective A3a/A3c, decision made). The orientation is pinned by mesh_gen pin-tests ("edges nearer/farther") and analysis (a measured 23.2° for toward vs ~39° for away), and the UV modes by UV-span tests; the pure diagnostics use the same arc formula with the sign from `bg.bulge`. `background_fit` inherits the current background's bulge and returns a `floor.present/suggested` suggestion (without a floor the bottom of the frame is not covered); the `render_still` report adds an `empty_frame` finding when empty_coverage > 2 % plus `objects_in_frame`/`objects_total` from the actual Bevy visibility of mesh parts; `validate` additionally reports `objects_out_of_frame` as an explicitly document-level root estimate against the cameras, and `skinned_shadows_unsupported` when opt-in shadows are combined with Phantom. The CLI `set-background` takes `--bulge/--fit`, and its help contains the coverage rule (horizontal coverage ≈ 2·asin(sin(arc/2)·R/dist) must exceed hfov); MCP `background_set` takes `bulge`/`fit` fields; the ffmpeg video decoder uses `-vf fps=24` (frame k ↔ k/24 s by timestamp, VFR does not break the mapping), a ring buffer, looping by restart, and rewinding to the start when scrubbing backwards; the 3×2 zones are RMS-averaged in approximate linear color → 6 point sources along the screen + ambient, identical in preview and export. A video background is silent: its audio track is not mixed (no separate decision was made on this).

The outline is a separate unlit inverted-hull pass after skinning: the same mesh with flipped cull-mode, vertices offset along their normals in screen space; it is not part of the lit material. Thickness is specified in output pixels. The character mesh requirement is continuous normals on silhouette edges (the builtin rig's normals are rounded), otherwise the outline tears at the faces. Export keeps explicit frame IDs, waits for the requested frame's readback and accounts for GPU latency; one `Readback` is submitted exactly once (the component is removed after submission, the observer lives until `ReadbackComplete`), so deferred GPU map callbacks never write into a closed channel. "Grab the current screen" is not an implementation of per-frame export.

Implemented (light and floor P0): the scene document stores `lighting: SceneLighting` (serde default — old scenes get the default setup) and `floor: Option<SceneFloor>` (serde default `None` — old scenes do NOT gain a floor). The light is a three-point key/fill/rim setup of directional sources with fixed directions (key — the slice's previous direction); the per-source settings are color (linear RGB), intensity (lux), enable, and a `shadows` flag; the 8000 lux key default approximates the previous look. Corrective A1/A2: `shadows` defaults to **false** and serializes as false with old projects — the "skinned mesh + shadow pass" path on Bevy 0.17/wgpu fails with a pipeline validation error (Uint32x4 joint indices are not passed into the shadow stage), so shadows are a deliberate opt-in (`shadow|noshadow` in CLI `parse_light`, `shadows` in MCP PLight) until the skinned shadow pipeline is fixed; enabled light works without shadows. Ambient from the background is no longer a constant: `ambient_from_background` computes a semi-desaturated color (50 % toward its own luma — the background does not tint the actors) and a brightness of `150 + 2000·mean_luma` lux (night ~190, day ~950, bright background ~1750); the zone PointLights were raised from 150 lm (~1–9 lux) to `250_000·(0.25+mean)` lm (hundreds of lux of fill light) — both formulas are pure and covered by unit tests. The shared forge-path camera (viewport and offscreen export render identically) carries LUT-free `Tonemapping::Reinhard`: TonyMcMapface requires the Bevy `tonemapping_luts` feature, which we do not ship, and left the offscreen camera without a valid pipeline. Reinhard adds no new dependency and gives a deterministic working path. The background arc screen's material stays unlit; tonemapping does not change its brightness relative to the previous balance. MSAA 4x (`Msaa::Sample4`) sits on the same camera. The floor is a matte (roughness 0.95, metallic 0) opaque plane at y=0 that receives shadows; with the floor off, the PNG keeps full alpha; with it on, the floor is opaque frame geometry (a transparent shadow-catcher is out of P0 scope). The `SetLighting`/`SetFloor` commands validate finiteness and non-negativity of colors/intensities before mutating, are atomic, and undo in one step. Surfaces: Session operations `lighting_set`/`lighting_get`/`floor_set`/`floor_get`, MCP `scene_lighting_set`/`scene_lighting_get`/`scene_floor_set`/`scene_floor_get`, CLI `set-lighting`/`set-floor`, and a "Light and Floor" panel in the GUI. Changing light/floor are ordinary document commands: they bump the revision and rebuild the GPU world through LiveSync.

Bake keeps transparent PNG projections plus camera, range, resolution, and dependency-revision metadata. Changes to pose, camera, materials, light, or an influential background invalidate the bake. For correct occlusion between several Phantoms and objects, the main final render uses the shared depth of the original 3D scene; the separate PNGs are derived layers, not a replacement for the depth buffer. Viewing baked projections is possible from a matched camera; an arbitrary new camera requires re-baking. Neither export nor toggling the view deletes the sources.

## Three drawing kinds

2D drawings are frames/exposures of raster layers in output coordinates. 3D strokes are points with thickness, color, and visibility time in scene coordinates, rendered as geometry. Drawings and Phantoms are not merged into one rig.

Implemented (2D): the document stores strokes (points, color, thickness, eraser mode), not pixels — the exposure raster is derived; one brush gesture = one command = one undo. The layer canvas is fixed (1920×1080) and scaled to the output resolution. An exposure holds until the next one; onion skin ±1 exposure is viewport-only. Compositing: offline — CPU over the readback buffer; live viewport — unlit quads in front of the camera with a texture cache keyed by stroke version.

Model paint uses hits against the visible deformed surface, barycentric UV, and writing the brush into a separate editable base-color texture. Texture tile changes form one undo operation. UV seams, overlapping UVs, and picking agreement with skinning each need separate verification: we do not promise seamless painting merely because raycast exists. Missing UVs must be diagnosed rather than writing into a random region. Auto-unwrapping is not the chosen solution.

## Film, audio, and media processes

A film is ordered references to scene and shot ranges, with no transitions. One film-time-to-scene-time mapping function is applied to both image and sound. Audio clips belong to a scene or to the film; a scene's audio is trimmed together with its range and is not mixed a second time at film level. The core mixer sums float PCM with volume/mute; preview and export use the same logic. Values are clamped to range before integer output; clipping is shown to the user.

Implemented (no audio): `FilmClip { id, scene, range, shot }` in the document, `film_map` — the single time mapping; MP4 video-only by streaming frames into ffmpeg's stdin; AAC comes with the audio step without changing the pipeline. There is no film preview in the viewport — export only.

Implemented (shots): `Scene.shots: BTreeMap<ShotId, Shot>` (serde default — old manifests without the field load empty and stay on the legacy path; there is no migration of old projects). `Shot { id, name, range, camera }`: the range lies within the scene (validated), and the camera is the same `Camera` type (keys + focal_mm); Phantoms, objects, background, and audio are shared with the scene. An empty shot map is legacy mode: a single `scene.camera` over the whole scene range, behavior unchanged. Camera selection is `Scene::camera_for_shot(Option<ShotId>)` (unknown id → legacy camera), and key interpolation is the single `Camera::sample` in core (shared by legacy and shots, viewport and export). The `AddShot`/`RemoveShot`/`SetShotRange`/`SetShotCameraKey`/`RemoveShotCameraKey`/`SetShotFocal` commands are atomic and undo in one step; `RemoveShot` also removes the film clips pointing at that shot in the same command, and `SetShotRange` retimes them (undo step `SceneAndFilmReplaced`). `FilmClip.shot: Option<ShotId>` (serde default `None`): a clip references either a scene range or a shot — in the latter case the clip's range must equal the shot's range (`AddFilmClip`/`SetFilmClipRange` validate). A shot clip maps into its scene's range through `film_map`/`film_map_clip`, so the scene's audio is not duplicated; film export renders a frame with the clip's shot camera. Surfaces: CLI `render --shot`, `film-add --shot`; MCP `shot_add`/`shot_remove`/`shot_range_set`/`shot_camera_key_set`/`shot_focal_set` and `film_add` with an optional `shot`, `render_scene` with `shot`; Session operations mirror MCP and `state_get` returns the shot list; the GUI shows the scene's shot list (add/remove/select active), the active shot sets the camera for the scene's viewport and export, and legacy single-camera scenes work as before.

Implemented (audio): scene and film tracks with volume/mute and clips on frames; the core mixer (mix_frame zeroes, mix_into layers — the contracts were separated after a bug where film tracks wiped scene audio); decoding to f32 48 kHz via ffmpeg; the film mixes its scenes through film_map plus film tracks, and export multiplexes AAC from a temporary WAV; cpal preview with a silent fallback when there is no device (per-frame feeding along the timeline rather than along audio time — a small preview drift is possible, export is frame-exact); a peak >1 is shown as clipping.

FFmpeg is launched by arguments without a shell; input paths and the output directory are validated. Process count, buffers, and probe duration are bounded; cancellation terminates processes and removes temporary files. There is no silent codec download from the network. `ffmpeg`, `ffprobe`, and support for the required decoder/encoder are checked; the binary's presence does not guarantee H.264. For predictable software output the original candidate is libx264 and AAC; when they are missing, MP4 export reports the reason and PNG stays available.

Encoding uses frames and PCM from a fixed range with matching timestamps. The project keeps being edited independently of the export job's snapshot. The result is published only after successful completion, and cancellation does not damage the previous file; existing output is never overwritten without explicit permission.

## Reuse and licenses

Bevy/bevy_egui (MIT/Apache-2.0) and ufbx (MIT/Unlicense) are the preferred narrow dependencies; the licenses of the specific pinned versions and of transitive components are checked before shipping. Blender/add-on code is not copied over automatically. FFmpeg has LGPL/GPL variants depending on the build; libx264 changes the license mix. Running it externally does not waive the licensing and possible patent questions of shipping codecs.

Selective source reading, not a full audit:
- FilmCraft h264enc/aac have relatively narrow APIs but require a bitstream and a pinned craft-media; a ready synchronous MP4 additionally needs a container and an export adapter. For the chosen external FFmpeg that is extra integration.
- TextureCraft formats/paint depend on core/texel/geom/compose and their mesh/UV/pixels models. Their FBX mesh API does not by itself prove that the rig and animation are preserved. Porting a whole paint editor was not chosen.

### Durable project-lock contract

Standalone `Session` and the GUI bridge use the same `.phantom.lock` record and guard. A current record contains a format version, PID, Linux process-start identity when `/proc` provides it, an unpredictable ownership token, optional bridge socket, and heartbeat timestamp (filesystem mtime is also reported). Acquisition is exclusively `create_new`; no `exists`-then-write path is permitted. Release and `Drop` reread the token and therefore never unlink a replacement owner. The GUI acquires before binding its Unix socket and drops the guard if bind fails. `project_new` acquires before manifest creation and drops the guard on creation failure.

A PID is live only when `/proc/<pid>/stat` exists and, when recorded, its start identity matches; a missing PID or reused PID is definitely dead and may be reclaimed with warning data. A tokenless legacy lock is reclaimed only for a definitely dead PID. Parse failures, inaccessible process state and non-local/ambiguous ownership are not silently removed; `force` is required, and even force never removes a definitely live lock. Bridge lock reads expose PID live/dead/ambiguous status and socket presence for diagnostics. `lock_release` reports the observed owner; a lock already owned by the calling session is an idempotent no-op.

A `Session` owns at most one guard. Reopening the same canonical directory returns `already_open: true` without reacquisition. Switching that Session to another directory is rejected (rather than risking unsaved state or stranding the old guard); clients create another MCP session to switch projects.

Extending MCP to the core commands (production access, stage 1): `state_get` also returns the Phantoms (id, name, rig kind, key/take/clip-usage counters), the film (clip id, scene, range, shot) and the scene and film audio tracks (id, name, volume, mute, clip count). Core commands previously unavailable to the agent are wired up as operations and MCP tools under the same names: `scene_range_set`, `shot_camera_key_remove`, `phantom_remove`, `motion_key_remove`, `motion_replace` (batched ReplaceMotion — one undo step), `background_clear`, `audio_track_remove`, `exposure_remove`, `layer_add_2d`. The internal Session/bridge `Op::TakeAdd`/`Op::MotionReplace` keep the legacy tuples and a parallel `yaws` for serialization compatibility, but the MCP boundary accepts only typed motion objects with `yaw_deg` inside each key. `background_set` was brought to parity with the CLI: optional `video`/`arc`/`radius`/`height`/`center`, with serde defaults equal to the previously hardcoded values (2.0 rad, 6.0 m, 4.0 m, [0,2,-5]); old bridge JSON parses. History is available to the agent: `history_undo`/`history_redo` (applied=false on an empty stack) and `history_list` (stack depths + names of the most recent operations). `render_scene` gained a `twos` flag ("on twos" mode) and `render_film` a `frames` range; both are passed through into the child CLI job's arguments. All operations go through the shared Session/Op dispatcher, so the standalone stdio mode and the bridge to the window receive them at the same time.

Stage 2 (corrective C3/D2–D4) adds queries and service tools: `shot_get`, `asset_get`, `film_get`, `project_recent`, `job_wait`, `describe` (see "Commands and MCP"). Verified by unit tests without a GPU: canonical snapshots and nearest ids for `asset_get`; getters do not bump the revision and do not add undo steps; round-trip and corruption of the recent-state file (a warning instead of a failure, healing on a successful open, the file holds only a path and a timestamp); `project_recent` with no project and no state file; `job_wait` — fast success, failure with a stderr tail and an exit code, timeout while the child process is alive (the child stays running and cancellable), zero timeout, the 0..=300 bounds, an unknown job; standalone/bridge parity for the getters and `job_wait`; `describe` matches `tools/list` field-for-field and returns `nearest_tools` for an unknown name. Stage 4 (corrective C3.4/A4) adds `audio_report`, `audio_summary` in `state_get`, and the `film_add` warning. Verified by unit tests without a GPU: RMS/peak in dBFS on synthetic PCM; a quiet/long fragment and reading past the source via a stubbed probe; per-clip decode_failed and degradation without ffmpeg/a directory; filtering by scene; `film_add` warns about a track longer than the clip and stays silent on a covering clip; an integration test with a real WAV (written through `write_wav` and decoded by ffmpeg, gated on ffmpeg being available) confirms that a quiet (−66 dB) and a loud (−6 dB) second of one file give different fragment RMS; the MCP contract: structure, not_found, no revision growth.

Stage 3 (corrective C3.8) adds an atomic `batch`: verified by unit tests without a GPU — a chain of five mutations with ids identical to the single calls, one revision and one undo; rollback of document/history/revision/next_id when a step fails in the middle; rejection of non-mutations, a nested batch, and an empty batch before the document changes; undo/redo of the whole package in one step with the same ids; the core-level `Command::Batch` (atomicity, `InvalidBatch`); an MCP tool with active-scene substitution, `invalid_input` with an index on a parse error, `batch_failed` with an index/inner code, and parity through the bridge. Validate/lint from corrective C3 is not implemented yet.

Verified partially or not verified: FBX import with skinning and clip playback are verified on the CC0 KayKit rig (41 bones, 9 meshes, 95 stacks); literal Mixamo files (hierarchy, skinning) were not verified in the render — a user file is needed; retargeting patterns were verified against the names of a user Mixamo file (unit tests, no render); the inverted-hull outline on models with open edges (a cloak, a collar) produces artifacts; clip stack selection always picks the longest one (never by name); editing/renaming/trimming takes and highlighting their range on the timeline are not implemented; 3D strokes and model paint are not implemented; the MCP live-recording mode is not implemented (key_set sets frames explicitly), and "on twos" is available in MCP only as the `render_scene twos` export flag; sample-accurate audio-clip trimming in the UI is not implemented; the video background texture is limited to 1280px; the interactive GUI paths (input, recording, drawing with the mouse, listening) were verified by model unit tests and manual runs, but not by automated UI tests. The outline is an inverted-hull pass (not a post-process over a mask/depth); the choice is recorded here as the slice's working solution: an unlit pass, separate from the lit material, exactly as the "Render" section required.

## Architecture verification

Before any claim that this works we need: one FBX with a rig plus a separate compatible clip; the same pose under direct seek and sequential playback; an offscreen PNG with outline and alpha; GUI/MCP parity; the twos check with a moving camera; take isolation; a project round-trip; export cancellation without corrupting files; movie cuts with audio and no drift; UV painting on a deformed model; failure without a GPU/codec, and MCP being barred from escaping the permitted root.

These are verification criteria, not tests already passed. Achievable speed, support for a specific Linux GPU/driver, the range of FBX materials, and the quality of the starter motions are unconfirmed. The architecture does not introduce network synchronization, universal retargeting, or a custom media codec as a way to hide these risks.

## Bundled procedural actors

`RigRef::Builtin` retains its legacy JSON string representation and humanoid
skeleton. `RigRef::BuiltinActor { actor }` adds explicit `Humanoid`, `Wolf`,
`Horse`, and `Bird` profiles. Builtin geometry and skeletons are generated locally
from original primitives, licensed by `BUILTIN-ACTORS-LICENSE.txt` (MIT, including
generated assets); unrelated repository assets are not bundled.

Supported actions are humanoid Idle/Walk/Jump; wolf Idle/Walk/Sit/Lie/Sneak;
horse Idle/Trot/Gallop; bird Fly/Perch. Profile-specific skeletons and stateless
pose sampling are shared by timeline evaluation and rendering. New key, motion
replacement and take commands reject incompatible actions atomically. Renderer
scene construction also diagnoses incompatible keys in loaded documents; pure
evaluation falls back to the profile default for malformed external documents.
Empty tracks and pre-roll use Idle, or Perch for birds. Mesh/skin caches are keyed
by actor profile. Coordinates remain Y-up, metres, forward +Z. Motion keys carry
root yaw about +Y in radians (serde defaults missing yaw to zero). Position and
yaw must be finite on deserialization, key/replacement/take commands and renderer
scene construction. Yaw follows the shortest angular arc deterministically;
position, yaw and pose use scene-relative twos and stateless seek. The shared
renderer applies root yaw for builtin and imported rigs, including live humanoid
control. Live humanoids face travel (+Z at zero yaw), retaining stationary/start
yaw; recording starts from evaluated timeline position/yaw. CLI set-key --yaw,
MCP `key_set` uses optional `yaw_deg` in degrees with preserve semantics; the Session edge and core use radians, while legacy `TakeAdd` triples still default yaw to zero. GUI timeline keys expose XYZ and yaw in radians.
No flight controller is added. Bird travel/height uses position keys (only a lower
bound at y=0, never forced to the ground);
perches/branches remain separate props.

The existing live Walk/Jump controller and its pose override are restricted to
bundled humanoids; other profiles and imported rigs stay timeline-driven rather
than receiving incompatible humanoid joints or recorded actions. Actor and
action names are shared by GUI, CLI, MCP and session dispatch through one
catalog (`crates/app/src/builtin.rs`), so all surfaces accept the same names:
GUI creation picks an actor from a combo and the timeline key action combo is
filtered by the actor's supported actions; CLI `add-phantom --rig` accepts
`builtin` (legacy), `humanoid|wolf|horse|bird` or an asset ID, and `set-key`
accepts all catalog actions; MCP `phantom_add` takes an optional `rig_actor`
(conflicting with `rig_asset`, which is preserved unchanged), `builtin_catalog`
returns profiles with actions and defaults, and `key_set`/`take_add` accept all
catalog actions. These are simple stylized rigid-weight low-poly models and
procedural motions, not realistic anatomy, locomotion or contact physics.
